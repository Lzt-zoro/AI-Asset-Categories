# 路线图

## 第一阶段（已完成，MVP）

- [x] 批量入库、递归扫描、mtime 增量、SHA-256 去重
- [x] PySceneDetect 硬切检测
- [x] 镜头内动作区间定位（帧差 + 滑窗评分），单镜头多候选
- [x] 虚拟切片，只记录路径与起止时间
- [x] 受控标签体系与别名归一
- [x] 可插拔 AI 标注（OpenAI 兼容多模态）
- [x] 人工修改、确认锁定、重新标注
- [x] SQLite 索引 + 多维/关键词检索 + 加权排序
- [x] 缩略图缓存、预览裁剪缓存
- [x] 本地 Web UI 与 CLI
- [x] 目录派生分类（层级筛选、父分类含子分类、单条片段可改分类）
- [x] `/api/v1/*` 稳定别名，供后续 Cutput 固定版本接入
- [x] 单元测试与真实视频冒烟

## 第二阶段（语义检索）

- 引入中文文本向量（bge-m3 / text2vec），片段描述与标签共同编码。
- 向量存独立表或 `.npy`，不写入 `clips` 主表；SQLite 先过滤再算余弦。
- 参考视频相似：对参考片抽帧取 embedding 均值，检索片段向量。
- 排序融合：`α·标签 + β·向量 + γ·动作 + δ·时长 + ε·画质`，权重可配置。
- 增量：源文件哈希或描述变化时才重算向量。
- 界面增加「找相似」拖入参考片段。

## 第三阶段（自动选材）

- 接受目标镜头规格（标签、描述、时长、景别、产品），返回 Top-N 与理由。
- 与 Cutput 的替换/拼接/导出流水线对接：素材库只读查询，Cutput 负责成片。
- 缓存预热：按项目命中频率提前裁剪高频片段。
- 批量任务队列、失败重试与进度持久化。
- 多库/多项目隔离（当前单库）。

## 暂不做

- 人脸身份识别、品牌真伪判断、功效宣称生成。
- 逐帧调用云端模型。
- 删除或改写源视频。
- 在本项目内实现成片渲染。

## 合并到 Cutput 的前提

1. Cutput V0.3 语义片段流程稳定并有金标评测。
2. 双方确认 `clip_id` 与 `ScenePlan` 的映射规则（本项目保留源 SHA-256 与区间）。
3. 接口以 `/api/clips` 为只读契约，避免共享 SQLite schema。
4. 迁移时只读现有库做一次性导入，不反向依赖本项目的表结构。
