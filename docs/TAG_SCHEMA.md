# 标签体系

标签是检索的主索引，因此必须受控。任何不在词表内的 AI 输出都会被丢弃。

## 三类维度

| 类别 | 维度 | 来源 |
| --- | --- | --- |
| 统一分类 | 分类 | 文件夹路径和 AI 画面用途共用一个维度，按 origin 区分 |
| AI 标签 | 分类、人物、景别、场景、动作、产品、情绪 | AI 看关键帧和可选字幕判断，受控词表 |
| 手动标签 | 光线、色彩、构图 | 只在人工编辑时可选，不发给模型 |

目录路径不进入 AI prompt，只有内置画面用途分类会发送给模型。`光线/色彩/构图` 保留词表是为了兼容历史数据和人工补充，但同样不发给模型，
因为它们对「找可用镜头」帮助有限，而每次调用都要多付 token。

## 分类规则

1. 文件夹分类取「扫描根目录 → 文件所在目录」的相对路径，层级用 ` / ` 连接；
   画面用途分类使用同一个 `分类` 维度，但由 AI/人工产生。两者通过 `origin` 区分，
   不会因为同名而互相覆盖。
   扫描 `\\NAS\ai` 下的 `疼点使用\疼点涂抹\a.mp4`，得到 `疼点使用 / 疼点涂抹`。
2. 直接放在扫描根目录下的文件没有分类（空字符串），不会硬造一个根目录名。
3. 分类存在 `sources.category`，同一源文件切出的所有片段共享它。人工改分类会同步到
   该源文件的全部片段，因为分类描述的是「这个素材属于哪个目录」。
4. 检索父分类会返回全部子分类：选 `疼点使用` 包含 `疼点使用 / 疼点涂抹`。
5. 目录名拼写不一致时，用配置里的 `category_aliases` 合并，**不改客户共享盘**：

```json
{
  "category_aliases": { "痛点": "疼点" }
}
```

   别名只影响入库结果：`痛点 / 额头疙瘩` 会变成 `疼点 / 额头疙瘩` 并合并计数，
   连续重复的层级会被去重。

## 归一规则

1. Unicode NFKC + 小写 + 去除空格与常见标点。
2. 先匹配别名表，再匹配规范名；跨维度歧义时以第一次命中为准。
3. 写入数据库时只保存规范名，别名只用于输入解析。
4. 标签来源：`origin='auto'`（模型）、`origin='manual'`（人工）、
   `origin='folder'`（目录分类）。重新 AI 标注只清除 auto，不动另外两类。
5. 每个维度最多 2 个 AI 标签；人工最多 4 个，避免标签膨胀。

## 别名示例

| 规范名 | 别名 |
| --- | --- |
| 近景 | 半身、近距、medium close-up、mcu |
| 涂抹 | 涂产品、上脸、抹开、涂开、apply |
| 祛痘霜 | 小蓝瓶、祛痘膏、痘痘膏、acne cream |
| 湿敷棉片 | 棉片、湿敷片、acne patch |
| 说话 | 口播、讲解、对镜头说话、talking |

完整表见 `material_library/tags.py` 的 `VOCABULARY`。新增标签需同时补别名与测试，
并保持既有 canonical 不变，否则历史过滤条件会失效。
