# AI 智能视频素材库 — 需求对齐（MVP）

本文件把用户需求固化为可验收的范围、边界与技术决策。它与 `ARCHITECTURE.md`、
`TAG_SCHEMA.md`、`ROADMAP.md` 一起构成项目的需求基线。

## 1. 目标

本地运行的视频素材库：批量入库 → 硬切镜头检测 → 镜头内动作片段定位 → AI 多维度
标签与描述 → SQLite 索引 → 多维/关键词检索 → 返回「原视频路径 + 起止时间」供剪辑
工具直接引用。

## 2. 本期（MVP，第一阶段）范围

| 能力 | 本期实现 | 说明 |
| --- | --- | --- |
| 批量导入 | 是 | 扫描文件夹，递归、增量、按内容 SHA-256 去重 |
| 硬切检测 | 是 | PySceneDetect，镜头写入 `shots` 表 |
| 镜头内动作定位 | 是 | 基于帧差运动能量定位动作区间，按时长与完整性选窗 |
| 虚拟切片 | 是 | 只记录 `path + start + end`，不生成重复文件 |
| 多片段 | 是 | 一个镜头可产出多个互不重叠的候选片段 |
| AI 标签/描述 | 是（可配置） | OpenAI 兼容多模态接口；未配置时降级为人工标注 |
| 统一标签体系 | 是 | 受控词表 + 别名归一，维度固定 |
| 统一分类维度 | 是 | 目录路径和 AI 画面用途共用「分类」维度，来源分开保存 |
| 人工修改 | 是 | 标签增删、描述改写、确认锁定 |
| SQLite 索引 | 是 | WAL 模式；关键词用 `LIKE` 子串匹配，FTS5 留到二期 |
| 标签/关键词检索 | 是 | 多维度筛选 + 关键词 + 综合评分排序 |
| 缩略图缓存 | 是 | 每个片段抽取 3 帧，按源文件哈希分目录 |
| 重复检测 | 是 | 同 SHA-256 标记为 duplicate，不重复分析 |
| 本地 HTTP 接口 | 是 | 供后续 Cutput 调用的只读查询接口 + OpenAPI |
| 预览 | 是 | 浏览器内区间播放 |
| 语义向量检索 | 否（二期） | 预留接口与字段，不在本期实现 |
| 参考视频相似匹配 | 否（二期） | 同上 |
| 自动替换/批量剪辑 | 否（三期） | 由 Cutput 负责，素材库只提供查询 |

## 3. 不做 / 约束

- 不修改 `D:\tools\shot_workbench`、`D:\cutput` 及其数据；本期无任何跨项目写入。
- 不破坏原始视频：所有产物写入本项目的 `data/` 目录。
- 不做人脸识别、人物身份识别、产品 OCR 真伪判断；AI 只输出可复核的描述与标签。
- 不在检索时触发视频分析；检索只读索引。
- 不把 embedding 数组写入 SQLite 主表（二期单独建向量表/文件）。
- 不做云端上传；AI 调用仅发送抽取的少量关键帧。

## 4. 关键决策

1. **片段 ID 稳定**：`clip_<hash(source_sha256, start_ms, end_ms)>`，重新分析不会丢失人工标签。
2. **AI 可插拔**：`labeling.py` 定义 provider 协议；默认 OpenAI 兼容 `/chat/completions`。
   未配置时流程不失败，片段标记 `needs_review`。
3. **动作定位在本地完成**：先用帧差选出候选窗口，再让 AI 描述/打标；不逐帧调用模型。
4. **评分显式化**：标签符合度、关键词相关度、动作完整度、时长匹配、画质各有权重，
   权重写在配置中，便于后续调参。
5. **接口独立**：`/api/*` 为稳定对外契约（字段只增不改）；UI 使用同一套接口，
   避免两套逻辑。加版本前缀时新增 `/api/v1/*` 别名，不删除旧路径。
6. **分类与目录对齐**：`分类` 是统一维度，同时承载扫描根目录到文件之间的相对路径
   和受控的画面用途分类。目录路径用 `" / "` 连接，连续重复层级去重；父分类计数
   包含全部后代，检索父分类自动命中子分类。目录路径不发送给模型；模型只选择受控
   的画面用途分类。目录拼写需要归一时，写在 `config.local.json` 的
   `category_aliases`，不改共享盘。
7. **辅助维度只做手动**：`光线 / 色彩 / 构图` 保留词表供人工补标，但不进入 AI
   prompt，UI 中折叠并标注「手动」。省下的 token 让 7 个主维度（分类、人物、
   景别、场景、动作、产品、情绪）判断更稳；`素材类型`区分普通素材和成片。

## 5. 验收标准（MVP）

- 给定一个包含 80 个视频的文件夹，`scan` 可增量入库，重复执行不重复分析。
- 对单个 5 秒视频，`analyze` 能输出至少一个 ≤ 目标时长且覆盖动作主体的虚拟片段。
- 片段卡片可预览真实区间，`path/start/end` 与画面一致（±1 帧）。
- 标签筛选 + 关键词组合检索返回排序结果和分数，响应不触发 FFmpeg。
- 重启服务后数据、人工修改、确认状态完整保留。

## 6. 待用户确认的假设

- 素材以竖屏电商短视频为主。普通素材优先输出一个完整动作的开始到结束，不为凑够
  3 秒混入其他动作；静态镜头才使用目标时长作为回退窗口。成片则按硬切保留完整镜头。
- 主要检索语言为中文，标签体系以中文为准；英文别名做归一。
- AI 使用任意 OpenAI 兼容多模态端点；默认模型名留空，需在 `config.local.json` 填写。
- 单机单人使用，服务只绑定 `127.0.0.1`。
